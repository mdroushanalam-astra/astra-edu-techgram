### ADR-001 — Runtime kernel in TypeScript; Python becomes the Lab — ACCEPTED (2026-10-02)
**Context:** the Python/FastAPI prototype (50/50 tests) proved the loop, but the v2x execution plan specified a shared client/server kernel for the offline-first, on-device moat (M5) — the hardest thing to retrofit.
**Decision:** build the brain as a pure TypeScript package (`kernel/`) shared by PWA and Node server; Python stays for simulation, calibration, fitting (`lab/`); the Python backend is archived as reference — its envelope rules and test contracts port; its runtime math is superseded.
**Rejected:** Python-only path (closes the on-device door; two-stack rewrite later costs more).
**Consequence:** the prototype's 50 tests become porting contracts; numeric engines seed the Python lab.

### ADR-002 — FSRS-lite replaces SM-2 at runtime — ACCEPTED (2026-10-02, from v2 ruling)
**Why:** SM-2 (1990) is a fixed heuristic; FSRS-style Difficulty/Stability/Retrievability fits empirical review data better and integrates with the belief engine's time update (forgetting + mastery = one coherent state). SM-2 survives in the Python lab as a baseline comparator.
**Consequence:** `memory.ts` stability/difficulty/retrievability with concept-type priors (factual 3d / conceptual 8d / applied 12d — assumed until ~50 reviews/student).

### ADR-003 — Graph-prior Kalman belief engine is the primary estimator; Elo is the second opinion; BKT demoted out of runtime — ACCEPTED (2026-10-02, from v2 ruling)
**Why:** BKT has identifiability issues and needs per-skill data we don't have; the rank-1 EKF over (μ, Σ) with a structural prior is what makes little-data inference work at all (one answer updates correlated concepts via Σ[:,c]).
**Consequence:** disagreement between Elo and filter → `model_disagreement` flag, wider bands, higher information value (the prototype's "preserve disagreement" principle survives in a new body).

### ADR-004 — The planner values learning under a MAINTENANCE assumption — ACCEPTED (2026-10-02, build sprint)
**Context:** with a pure decay discount, the planner concluded learning 29 days before an exam was near-worthless (S=3–12d) and spent its days on 10-minute diagnostics; it lost to a random scheduler (125 vs 144 marks).
**Decision:** learn/practice/remediate gains are modelled with d=1 (the plan's own review schedule maintains taught concepts to exam day); reviews are valued by real stability growth. Receipts carry "assumed; maintained by plan reviews".
**Cost/risk:** if the plan fails to maintain (adherence collapse), realized gains < modelled — monitored via prediction_error on receipts; the sim's review mechanics validated the assumption (148 vs 149 marks of ideal fixed order).
**Evidence:** EXPERIMENTS §4 progression table.

### ADR-005 — Two-pass day fill; the review quota is a floor, not a lid — ACCEPTED (2026-10-02, build sprint)
**Context:** the single-pass fill skipped every high-value block while the review quota was unmet, then found fewer review minutes than the quota → 15-minute days (starvation).
**Decision:** pass 1 secures due reviews up to `min(minReviewShare, available review minutes)`; pass 2 fills remaining minutes by score. Block cap = floor(minutes/15).
**Evidence:** day plans went 15–30 min → 225–240 min; marks 130.6 → 148.3 (EXPERIMENTS §4).

### ADR-006 — Spacing rule at the event fabric: same-day responses = one memory review — ACCEPTED (2026-10-02, build sprint)
**Context:** one 25-min block emitting ~3 item responses tripled kernel stability per sitting (S≈13d vs truth ≈3.6d); the kernel stopped scheduling reviews and truth decayed.
**Decision:** `applyEvent` updates memory at most once per concept per logical day; belief still updates per response. Massed practice is one review; spacing is what grows stability.
**Evidence:** EXPERIMENTS §4; the spacing effect (Cepeda 2006) grounds it.

### ADR-007 — Prerequisite gate = ordering, not certainty — ACCEPTED (2026-10-02, build sprint)
**Context:** gating on belief σ(μ)≥0.55 lagged teaching by ~a day and idled dependent concepts (24/40 coverage).
**Decision:** gate opens on σ≥0.55 OR (nEff≥2 AND σ≥0.45). A prereq taught-and-failed (σ<0.45) stays shut — remediation is the task; an unstudied prereq blocks outright (property preserved: no hard-prereq skipping).
**Consequence:** param `prereqFloor=0.45` added; unlock cascade no longer starves days.

### ADR-008 — Paper-scale consistency for marks — ACCEPTED (2026-10-02, build sprint)
**Why:** blueprint weights summed to 19 questions but the paper is 100; expectedScore, trueExamMarks and planner gains must share one scale (×questions/Σw) or receipts contradict scenarios.
**Consequence:** all marks outputs are full-paper scale (~200); internal comparisons unchanged.

### ADR-009 — Diagnostic stops in the 20–25 item window — ACCEPTED (2026-10-02, build sprint)
**Why:** the early-stop (scoreSd < 4.0) fired at 10 items, under-delivering the honest-band promise; v2x specifies 20–25 items or a sd target.
**Decision:** early stop only at ≥20 items; max 25. Results screen stays bands + sharpen actions, never a bare percentage.

### ADR-010 — G0-lite measured as an archetype AGGREGATE, not single-seed/single-archetype — ACCEPTED (2026-10-02, build sprint)
**Why:** a consistent student on an ideal fixed order is the planner's hardest case (single-seed margins ±1 mark); the gate's claim is adaptation value, which only appears across archetypes.
**Decision:** CI gate = aggregate over 4 archetypes × seeds (30 days); single-archetype numbers still recorded in EXPERIMENTS §5 for honesty.

### ADR-016 — G0 redefined: four simulator worlds — ACCEPTED → **IMPLEMENTED** (2026-10-02, commit `b44fa3c`)
**Decided by:** GLM-5.3-Flash via ZCode, adopting ChatGPT's critique; founder-directed.
**Old G0:** "planner beats baselines in our simulator." **Necessary but insufficient — a simulator built from the planner's own assumptions can crown the planner in a world designed to agree with it.**
**New G0:** *"the planner remains useful — superior or competitive vs baselines — across multiple, partly unseen generative worlds":*
- **World A (Friendly):** truth generated per Techgram assumptions (current lab).
- **World B (Misspecified):** different forgetting dynamics, different gain magnitudes/ordering, heavier response noise, prereq edges that barely matter in truth.
- **World C (Adversarial):** halved gains, overreported confidence on every response, 30% of concepts pre-mastered against the prior, availability collapse mid-schedule.
- **World D (Hidden benchmark):** `kernel/src/lab/worlds.hidden.json` — **sealed** at FNV-1a `c31cd9d5` (UTF-8 bytes), hash pinned in `test/g0_worlds.test.ts`; any tamper fails CI. Rotate only via a new ADR.
**Implementation:** SimWorld configs in `lab.ts`; production AOM fixed across all worlds (the brain is never told which world it is in); per-registered pass rule in `test/g0_worlds.test.ts` with a visible results table.
**Results:** planner superior in A (+0.43 vs best baseline), strongly superior in B (+5.31), C (+4.11), D1 (+5.22), competitive-superior in D2 (+1.42) — the edge GROWS as worlds diverge from assumptions. Full table: EXPERIMENTS §10.
**Claim discipline:** public claims cite World D results or real-pilot data only. Worlds A–C are named as friendly/misspecified/adversarial in Brain Lab.

### ADR-018 — The Personalization Doctrine: measured behaviour over guessed emotion — ACCEPTED (2026-10-02)
**Decided by:** Founder's directive ("the intelligence layer should understand human patterns, emotions, behaviours better than any LLM; personalization so personal") + GLM-5.3-Flash adjudication.
**The honest reframe:** an LLM *guesses* a student's state from the vibe of one message — instantaneous, uncalibrated, unverifiable, forgotten tomorrow. Techgram **measures**: longitudinal behavioural evidence (response-time distributions, confidence-vs-accuracy calibration, hint ladders, answer-changing, abandonment minute, avoidance patterns, time-of-day adherence, review compliance) + belief probes the student answers in one tap. Over weeks this is a *calibrated, private, receipt-backed model of how this human actually learns* — which is strictly more reliable for personalization than any single-shot emotional read, and it improves with every session while an LLM's guess does not.
**The law (unchanged, now explicit):** we model **observable learning and engagement behaviour**; we do NOT diagnose emotion or mental state; no labels ("avoidant," "anxious") are ever emitted to anyone — internal hypothesis distributions drive *action changes only* (lighter plans, rest, human-referral nudge). This is simultaneously an ethics/compliance wall (minors, DPDP, no clinical claims) and a product advantage: parents and students trust measured facts over psychological guesses.
**Consequence:** B9 Behaviour engine priority is RAISED (it is the personalization engine), with the expanded signal set from the v2 notebook (§7.2) and the probe pattern (§7.4); B9's outputs feed the planner as context features (fatigue cost, session-length adaptation) — the concrete mechanism of "so personal."

### ADR-023 — The Engagement Ethics Wall + the Observable-State Law — ACCEPTED (2026-10-02)
**Decided by:** Founder directive (hyper-personalisation + retention ambition) + GLM-5.3-Flash (Z.ai) via ZCode, with the external review's language amendment adopted.
**The Observable-State Law (binding formulation):** *Techgram builds an increasingly detailed, explicitly uncertain model of the student's OBSERVABLE learning state and behaviour, and uses that model to choose better learning actions.* All personalisation signals (momentum, fatigue, frustration, avoidance, chronotype, recovery) are **observed/inferred behavioural features** — never claims of direct access to internal mental state, never diagnosis, never student-facing labels.
**The Engagement Ethics Wall (banned, test-enforced where possible):** guilt/shame mechanics · false urgency · variable-reward exploitation · emotional-state targeting to extract engagement · engagement-maximisation at wellbeing's expense · dark patterns per India's CCPA Dark Patterns Guidelines (2023). The legal frame: several such tactics are already regulated in India; and trust is our declared moat — exploitation burns it.
**The ethical retention engine (what we build instead):** right-sized sessions (measured load tolerance) · visible progress (belief-band narrowing) · continuity (MEMORY_OPEN) · timely respectful nudges (measured chronotype window, anti-nag backoff) · every retention mechanism instrumented as an experiment with receipts. **Wellbeing outranks engagement — invariant 7 applies to every experiment.**
**Rejected:** "breach ethics, keep legality" as an operating principle — it is strategically self-defeating for a trust-moat product, partly illegal already (CCPA dark patterns), and a violation of the ratified Charter.

### ADR-024 — Personalisation State v1 (B9 enrichment) — ACCEPTED (2026-10-02)

### ADR-025 — Return Model v0 + Engagement Experiment framework — ACCEPTED (2026-10-02)

### ADR-029 — The Allocation Principle + Agency Transfer + the Ship Mandate — ACCEPTED (2026-10-03)
**Decided by:** Founder directive + GLM-5.3-Flash via ZCode, adopting the third external review (ChatGPT, "Allocation Principle" framing).

The existing planner, AOM, personalisation state and evidence loop already implement this — the principle is a *framing*, not a new subsystem.

**The one sentence:** *"Given this particular human, this goal, this moment, this evidence, this uncertainty and this limited cognitive budget — what is the highest-value thing to do next?"* And then: *"Did it work?"* And eventually: *"Can the human now make that decision themselves?"*

### ADR-037 — SELF-DISCOVERY OVER SELF-MONITORING: the S-series replaces the G-series — ACCEPTED (2026-10-04)
**Decided by:** the Founder adjudicating the external critique of ADR-036's G-series; GLM-5.3-Flash via ZCode concurred with the critique on the merits.
**The critique accepted (it was correct):** (1) the G1 "Genesis" was benchmarking — capability probes → calibration → SelfModel is a report, not self-discovery; the missing ingredient is **self-generated inquiry** (the system notices uncertainty about itself, chooses its own probes, revises). (2) G2 conflated world-prediction with self-prediction — predicting session outcome is P(world | action); true self-prediction is **P(self behavior | state)**: "I predict I will choose retrieval over explanation when uncertainty > 0.35", checked against actual behavior. (3) G3 was parameter tuning; real improvement is **strategy-level** (and ultimately representation-level: revising the internal causal model, e.g. resistance = prerequisite failure + overload, not motivation). (4) The claim "replay rebuilds the mind" was overstated — replay rebuilds deterministic state; a mind requires accumulated experience to change the model generating future cognition.
**The adopted distinction:** self-monitoring (the system is measured) vs **self-discovery** (the system investigates itself, predicts its own behavior, catches its own errors, changes its strategies). The threshold: *accumulated experience changes the model that generates future cognition.*
**The S-series (replaces the G-series, pre-pilot):**
- **S0 SelfModel contract** — capabilities, limitations, calibration, knownUnknowns, activeHypotheses (about the system), recentSelfPredictionErrors.
- **S1 Self-prediction** — 3–5 predictions per session about the system itself: decision confidence, expected action outcome, expected intervention timing, expected uncertainty, expected performance. Logged before acting.
- **S2 Self-error ledger** — prediction / actual / error / pattern, from the executive's own receipts.
- **S3 ONE self-improvement experiment** — strategy-level: hypothesis → Strategy A vs Strategy B → simulator → external evaluation → retain/reject. First candidate: "I intervene too early when uncertainty is high."
**Genesis reframed:** a developmental PHASE, not a permanent organ — self-uncertainty → self-chosen probes → self-model update → the life loop; re-investigation when self-model uncertainty rises. Self-generated inquiry bounded deterministically: VoI (CAT machinery) applied to self-uncertainties.
**The eight acceptance tests adopted:** (pre-pilot, in-simulator) self-model accuracy, self-correction, reversion resistance, self-generated inquiry; (post-pilot/lab) historical dependence, strategy evolution, persistence, transfer.
**Naming law:** boring names in the architecture (SelfModel, Prediction, Appraisal, Memory, ValueModel, Executive, ImprovementLoop, DevelopmentalState); never consciousness/soul/identity-generator. The claim stays: "designed around general cognitive primitives" — the pilot judges.
**Unchanged:** frozen organs, external evaluator independence, Techgram as first world, divergence lab post-pilot, content sprint as critical path.

**The law:** before every meaningful action — WHAT AM I DOING / WHY / WHAT DO I EXPECT / WHAT WOULD CHANGE MY MIND. The Conductor executes; the Presence Layer expresses; neither decides. Intelligence is exposed selectively (Why-this as part of the experience, the cognitive microscope, visible self-correction: "I changed my mind" moments).
**Adopted from the companion critique:** epistemic agency as first-class (self-directed VoI over self-uncertainties — deterministic, CAT machinery pointed at the self) · three depths of self-modification allowed architecturally (parameter / strategy / representation) · Genesis reframed as bounded **Developmental Initialization** (self-directed VoI probes → SelfModel₀) · developmental path-dependence as the ultimate property (identical systems + different experiences → measurably different cognition) · the correction accepted: replay rebuilds deterministic state; a mind requires accumulated experience changing the model generating future cognition.
**The demo gate (binding):** "Can Techgram make a skeptical stranger say: Holy shit — it noticed that about me, tested it, was wrong, changed its approach, and got better?" The 3-minute demo: minute 1 knows nothing → hypothesis; minute 2 tests it → "I was wrong" → strategy change; minute 3 new intervention → "what I learned about you today" + "what I'm still uncertain about."
**Build sequence:** Stage A the engine (S0–S4 per ADR-037 as upgraded) → Stage B the body (Experience Plan + Conductor + Presence + Evidence UI) → Stage C the proof (3-minute demo + G4 + deploy). The interface polish comes LAST — not the other way around.

### ADR-039 — THE COGNITIVE RUNTIME REFINEMENT: one spine, two layers, the ExperiencePlan seam — ACCEPTED (2026-10-04)
**Decided by:** the Founder; GLM-5.3-Flash via ZCode adopted the external roadmap refinement wholesale.
**The reframing:** C-series (C1–C5) = EXECUTION INFRASTRUCTURE for the cognitive runtime. S-series (S0–S4) = DEVELOPMENTAL COGNITION — capabilities OF the runtime, not a separate subsystem. The old framing ("the engine stops being a sequence and starts being a mind") is deleted; the precise claim: the engine becomes an **evidence-conditioned closed-loop controller**.
**The refined C-series:**
- **C1 Cognitive Runtime Spine** — Workspace + Executive + Directive + Decision Receipt + candidate actions. The Workspace assembles per turn: goal, focus, beliefs, uncertainties, active hypotheses, evidence, time budget, plan progress, personalisation state, fatigue/load, relevant predictions, recent prediction errors, SelfModel, candidate actions, constraints. S1 hooks directly into it: SelfModel → "I predict I will choose X" → Executive → chooses X → SelfErrorLedger. **C1 is the spine connecting S0–S4 to actual cognition.**
- **C2 Developmental Cognition** — S0 Genesis/self-inquiry, S1 self-prediction, S2 self-error ledger, S3 self-directed inquiry, S4 self-improvement — as capabilities of the runtime, not a giant new subsystem.
- **C3 Communication & Expression** — DEMOTED to expression policy: tone, verbosity, humor, silence, board usage. "Humor doesn't decide whether the student needs retrieval — the brain decides retrieval; communication decides a short joke would be useful here."
- **C4 LLM Bridge** — downstream of cognition; M0-off first (S0–S4 must work LLM-off; LLM-on makes the experience richer, not the brain smarter).
- **C5 Session Conductor** — the execution layer. The Executive NEVER renders UI directly: Executive → ExperiencePlan → Conductor → Presence/Expression → UI.
**THE MISSING SEAM — the ExperiencePlan contract:** the typed handoff between Executive and Conductor: { learning, evidence?, communication, presentation, presence, agency?, expectedOutcome: PredictionRef, rationale: DecisionReceipt }. This is the seam that was missing.
**Build order:** C1 spine → S0 → S1/S2 → C5 conductor → S3/S4 → C2/C3 polish. Not sequential C1–C5+S0–S4 — the developmental loop must exist before expression is polished.
**THE FIVE PRE-PILOT QUESTIONS (the gate):** 1. Can it decide? (Workspace → Executive → Decision) 2. Can it explain why? (Decision → Evidence → Receipt) 3. Can it predict itself? (SelfPrediction → Action → Actual → Error) 4. Can it investigate itself? (Unknown → VoI → Self-experiment → Evidence → SelfModel update) 5. Can it change how it behaves? (SelfError → hypothesis → alternative strategy → test → retain/reject → future decisions change). **If those five work — stop building cognitive architecture and put it in Techgram.** The user should never see "SelfPredictionError #17" — they should experience: "It thought I needed another explanation. I actually needed to try it myself. It noticed that pattern and changed how it teaches me."

### ADR-040 — THE DEVELOPMENTAL LOOP CLOSED: the S-series composed into the Executive — ACCEPTED (2026-10-04)
**Decided by:** the Founder (gate order after the YELLOW forensic audit); GLM-5.3-Flash via ZCode implemented.
**Context:** the forensic audit (commit 9c390db) proved with a counterfactual that the developmental loop was OPEN — S0–S4 existed as unit-tested functions but disabling them changed NOTHING in the Executive's behavior. The five pre-pilot questions [ADR-039] were answerable only for 1 and 2.
**The decision:** the S-series becomes part of the Executive's decision pipeline via `cognitive/developmental-session.ts` (the composition the roadmap demanded, not a new subsystem):
1. **S1 BEFORE every decision:** the session emits self-predictions (`selfPredict`) before `decide()` runs.
2. **S2 AFTER every turn:** predictions are judged STRUCTURALLY against the measured turn actual (category vs outcome — not string overlap); real errors enter the SelfErrorLedger with pattern tags; experience-grounded judgments (intervention didn't help / premature break / fatigue collapse) enter independently of predictions.
3. **SelfModel consultation:** `deriveSelfInsights()` maps the ledger to self-knowledge (interventionTendency, breakCalibration, recurringPatterns, selfErrorCount) and it is INJECTED into the TurnWorkspace. Every insight has a behavioral lever in `generateCandidates` (early→evidence-first diagnose; aggressive→break ×0.6; reluctant→break ×1.25; late→interventions ×1.2; ≥3 errors→caution margin).
4. **The counterfactual switch is architecture:** `learningEnabled:false` records the same experience but never injects insights — the loop-closure test runs both and requires divergence.
**The gate evidence (EXPERIMENTS §17):** counterfactual INTEGRATION-TESTED (turn-4 divergence, persisted); deep gate re-run — executive beats linear on TRUE MARKS 12/12 seeds (12 vs 10 at seed 7331), belief error halved, Conductor executes every decision (80 plans/390 steps). Two world-honesty fixes declared: 8-turn days (fatigue must be expressible) and learning-follows-the-outcome (correct retrieval teaches ~5× a miss — payoffs identical for both policies).
**The limits (honest):** all evidence is SIMULATED-world; insights currently cover intervention timing, break calibration, confidence calibration — deeper self-model evolution (strategy experiments changing generation code paths — S4 level 2/3) remains future work; real-student efficacy UNKNOWN UNTIL PILOT.
**Five pre-pilot questions after this ADR:** 1 decide ✓ 2 explain ✓ 3 predict itself ✓ (self-predictions before every decision, judged) 4 investigate itself ◐ (patterns detected; VoI self-inquiry exists, not yet loop-critical) 5 change how it behaves ✓ (counterfactual-proven). The developmental loop is CLOSED in simulation. Next: Phase 4 expression is still GATED behind the founder's order.

### ADR-041 — S4 IN THE LOOP: live strategy experiments with external keep/reject — ACCEPTED (2026-10-04)
**Decided by:** the Founder ("go for it then, stop when we're ready for Phase 4"); GLM-5.3-Flash via ZCode implemented.
**Context:** ADR-040 closed the developmental loop with FIXED levers — insights changed decisions through hardcoded multipliers. That is adaptation, not IMPROVEMENT: nothing ever tests whether a different strategy would have worked better.
**The decision:** the Executive's own tunables become an explicit, versioned `StrategyParameters` block (DEFAULT_STRATEGY = the deep-gate-validated values). The S4 runtime (`strategy-experiments.ts`) closes the improvement cycle:
1. **PROPOSE** — a ledger pattern (≥3 same-tag self-errors) yields ONE falsifiable proposal: a parameter delta with its observation attached. No evidence, no proposal. Deterministic, bounded, one at a time.
2. **TEST** — a matched A/B in the simulator harness: identical world, identical seeds, identical student truth; ONLY the strategy parameter differs; metric = TRUE learning (external to the proposer); multi-seed averaged.
3. **KEEP/REJECT** — via the S4 organ (`runSelfImprovementExperiment`); a tie REJECTS (a change must EARN adoption); the record (with real A/B numbers) is append-only evidence.
4. **ADOPT** — kept parameters become the session strategy (`DevelopmentalSession config.strategy`); future decisions run under them; rejected experiments change NOTHING.
**The gate evidence [EXPERIMENTS §18]:** the full epoch is INTEGRATION-TESTED — session-1 experience → proposal → KEEP (+0.013 true learning in cheap-fatigue economics) / REJECT of the SAME proposal (−0.018 in punishing-fatigue economics) → session-2 decisions differ under the adopted strategy (fewer breaks) and are IDENTICAL under rejection → phase2Gate PASS (v0→v1 + evidence + decision change). The divergence is exercised on a seed where the marginal turns actually arise; multi-seed averaging guards the verdict.
**The limits (honest):** the parameter space is deliberately Level 1–2 (parameter/strategy per ADR-037) — representation-level self-modification (Level 3) stays on the not-built list; the harness is a compact declared-constants world, not the full four-world harness; all evidence SIMULATED.
**Standing after this ADR:** the five pre-pilot questions ALL pass (investigate-itself now ✓ — patterns drive experiments). The cognitive frontier is CLOSED. Per the founder's order, the next build is PHASE 4 (expression) — explicitly gated on the founder's go.

### ADR-042 — PHASE 4 EXPRESSION: the decision becomes experience, the LLM never decides — ACCEPTED (2026-10-04)
**Decided by:** the Founder ("go"); GLM-5.3-Flash via ZCode implemented per roadmap §10.
**The law restated:** Executive decides → Conductor executes → Presence expresses → LLM voices → UI renders. Never the reverse. Expression EXPRESSES the cognitive decision; it does not create it.
**What the layer owns (and nothing more):**
1. **Communication Policy [§10.1]** — verbosity (overloaded → terse, grey → deep), humor gating, silence-first. Proven not to change the directive it is given.
2. **Utterances under the claim-provenance law** — `validateUtterance` throws on missing evidence; the ETHICS WALL is enforced at the voice (guilt/urgency phrasings throw). Unproven claims may not be spoken.
3. **The microscope** — why-this (the receipt's reasons AND what was given up) and earned self-correction from real ledger patterns: the student hears "it noticed, it was wrong, it changed" — never machinery IDs, at most one per 3 turns, null without evidence (no performed humility).
4. **Praise hybrid (c)** — warm + specific + TRUE: earned by two observed corrects, concept-named, evidence-carrying, capped.
5. **Density control** — deterministic rotation, no repeated reassurance within 3 turns, breaks carry one line, silence produces zero utterances.
6. **Board payload [§10.2]** — structured references only; teaching content stays with the frozen teacher via the learning channel.
7. **Prosody** — interruption non-negotiable; struggling student gets slow+low.
8. **LLM Bridge [§10.4]** — bounded re-voicing (paraphrase/example) ONLY where the Executive chose augmentation; basis = the utterance's evidence; constraints carry the ethics wall; the deterministic text is always the fallback.
**THE PHASE 4 GATE (the binding one):** LLM OFF vs LLM ON — identical utterance text + evidence at the utterance level; byte-identical deep gate at the session level (true marks, receipts, plans, conductor steps, self-errors, breaks). The bridge cannot make the brain smarter. Purity proven: expression mutates nothing it is given.
**Seam refinement (discovered BY this gate):** the ExperiencePlan seam's "non-rest must carry evidence or expression" rule rejected silent and voice-only plans — silence is a first-class presence and the learning channel always carries the turn. Amended; the pinned invariants (six channels, learning action required) unchanged.
**The limits (honest):** kernel-level evidence — the product rendering of these utterances (board, orb, voice tiers) rides the Phase 5 adapter + frontend v4; Hinglish/localization is an adapter concern; all evidence SIMULATED-world.
**Standing:** Phases 0–4 all complete at kernel level with gates earned. Next per roadmap: Phase 5 (Techgram World Adapter) — GATED on the founder's direction.
